# Failure Mode and Effects Analysis (FMEA)
# TeaAgent — 2026-06-02

**Scope:** Interactive surfaces (`teaagent chat`, `teaagent tui`) and supporting subsystems.  
**Method:** Code-grounded review of seven major processes. Findings cross-referenced against
the 2026-06-01 daily-driver review package (CG-01…CG-16, AG-01…AG-04, PR-1…PR-8, threat-model.md).  
**Scoring:** RPN = Severity (S) × Occurrence (O) × Detection Difficulty (D), each 1–10.

> S: 1–3 edge/info, 4–6 minor/degraded, 7–9 major user-facing, 10 data loss/security  
> O: 1–3 rare/theoretical, 4–6 occasional, 7–9 frequent, 10 every invocation  
> D: 1–3 easily detected, 4–6 moderate, 7–9 hard to detect, 10 undetectable without instrumentation

## P1: Chat Session Initialization

**Description:** The sequence from `teaagent chat "task"` or `teaagent tui` launch through
REPL/TUI ready-state — including initial task injection, session state setup, LLM adapter
creation, audit logger bootstrapping, and config loading.

| ID | Failure Mode | Effect | S | O | D | RPN | Mitigation Status |
|----|-------------|--------|---|---|---|-----|------------------|
| FM-CSI-01 | Initial task string not forwarded from CLI to TUI REPL | User types a task as CLI arg, TUI opens empty; task silently dropped | 7 | 6 | 4 | 168 | **FIXED** — commit `47710d9` (TASK-DD2-001) passes `initial_task` through `TUIApp.__init__` |
| FM-CSI-02 | TUI session cost counter initialized to zero and never incremented | `/cost` and budget bar display `$0.00` for entire session regardless of actual spend | 7 | 10 | 5 | 350 | **OPEN** — CG-11; stop-gap `+=` in `_run_agent_task` landed but root fix (TICKET-12) not yet merged |
| FM-CSI-03 | LLM adapter creation fails (unknown provider string or missing credentials) | Session fails to start; error may be cryptic (KeyError or ValueError from `create_llm_adapter`) | 8 | 3 | 3 | 72 | Partial: error propagates to CLI as exception; no user-friendly message |
| FM-CSI-04 | Audit log directory creation fails (disk full, missing parent, bad permissions) | Session starts without audit trail; failures silently degraded | 8 | 2 | 7 | 112 | `AuditLogger.__init__` calls `mkdir(parents=True, exist_ok=True)`; no feedback to user on failure |
| FM-CSI-05 | Workspace config file (`config.json`) malformed or schema-invalid | `load_workspace_config` returns partial dict; downstream consumers use wrong defaults silently | 6 | 3 | 8 | 144 | No schema validation on load; no warning emitted |
| FM-CSI-06 | TUI and REPL controller divergence — same bug fixed in one surface, silently remains in other | User on TUI sees different behavior than docs/REPL describe; trust erosion | 8 | 10 | 6 | 480 | **OPEN** — CG-12 / TICKET-12; root cause: TUI never adopted `ChatSessionController` |
| FM-CSI-07 | Race between config load and first tool call (no lock on config hot-reload) | Tool call uses stale permission mode from previous config if reload happens mid-session | 5 | 2 | 9 | 90 | Theoretical; config loaded once at session start in practice |

**Top risk:** FM-CSI-06 (RPN 480) — surface divergence is the root cause of every TUI-specific correctness gap.

## P5: Undo

**Description:** The `/undo` command path in both REPL and TUI — from user invocation
through `UndoJournal.restore()` (REPL) or git-stash restore (TUI), to workspace
reconciliation and audit recording.

| ID | Failure Mode | Effect | S | O | D | RPN | Mitigation Status |
|----|-------------|--------|---|---|---|-----|------------------|
| FM-UN-01 | TUI `/undo` uses git-stash checkpoint (broad); REPL `/undo` uses UndoJournal (surgical) | Same command word, different blast radius: TUI can revert manual edits outside the run | 8 | 7 | 5 | 280 | **OPEN** — CG-15 / TICKET-12; known-issues doc warns users; no unified implementation |
| FM-UN-02 | `UndoJournal.save_to()` failure silently swallowed in `ChatSessionController` (CG-13) | Run completes, user types `/undo`, journal is empty; undo is a no-op with no warning | 8 | 4 | 9 | 288 | **OPEN** — `chat_session_controller.py:143–159` catches `(AttributeError, TypeError)` too broadly; real I/O failures pass through but not logged to user |
| FM-UN-03 | Shell tool (`workspace_run_shell`) writes not captured by UndoJournal (no stable path arg) | Shell-based mutations cannot be undone via `/undo`; silent gap | 7 | 6 | 7 | 294 | By design (documented); `_PATH_WRITE_TOOLS` frozen set; user should use sandboxed tools |
| FM-UN-04 | Path traversal via `..` segments in undo journal entry escapes workspace root | Restoring a crafted journal entry overwrites files outside workspace | 9 | 1 | 5 | 45 | `_extract_checkpoint` and `UndoJournal` resolve paths against `root`; `..` escape silently ignored (`run_undo.py` guard) |
| FM-UN-05 | Undo restores a file that has since been deleted externally (file not found error) | `restore()` raises or returns partial result; `errors` list populated | 5 | 3 | 3 | 45 | `UndoResult.errors` captures failures; `ok` property returns `False`; user sees error |
| FM-UN-06 | Concurrent undo operations on the same workspace (two REPL sessions open) | Double-restore corrupts file state; second undo operates on already-reverted content | 7 | 2 | 7 | 98 | No lock on workspace-wide undo; `file_lock` per-file but not session-wide |
| FM-UN-07 | REPL `/undo` help text describes the old `git checkout -- .` behavior (stale docs) | User has false mental model of undo blast radius | 4 | 8 | 4 | 128 | **OPEN** — CG-15 notes stale help text at `chat_repl.py:168` |

**Description:** The `teaagent chat` `/background` command, the resulting `suspension-<id>.json`
checkpoint, and every follow-up resume path (`teaagent resume`, `agent run --background`,
`agent interactive-review`).

| ID | Failure Mode | Effect | S | O | D | RPN | Mitigation Status |
|----|-------------|--------|---|---|---|-----|------------------|
| FM-SR-01 | `teaagent resume <repl-id>` always fails: `task_for_run` raises `ValueError` because no `run_started` event was recorded for REPL-originated suspensions | User follows the printed instruction; gets `{'status':'error'}`; no recovery path | 9 | 10 | 3 | 270 | **OPEN** — AG-01 / TICKET-16; `run_store.py:143–149` raises on missing event |
| FM-SR-02 | `agent run --background <id>` silently starts a new run with the run_id as literal task string | User thinks they are resuming; a bogus run is created; budget consumed; original session lost | 9 | 8 | 8 | 576 | **OPEN** — AG-02 / TICKET-16; no guard in `_agent.py:145`; silently does wrong thing |
| FM-SR-03 | Saved suspension context (`observations`, `config`) never rehydrated into resumed run | All prior session context lost on resume; agent starts from scratch despite checkpoint | 8 | 10 | 4 | 320 | **OPEN** — AG-03; `suspend_to_background` writes JSON correctly but `agent_resume_command` reads from `RunStore`/checkpoint, not the JSON |
| FM-SR-04 | Three follow-up commands printed post-suspend: two broken/misleading, one working | User picks the wrong command; session data lost or new bogus run started; trust in honesty model undermined | 8 | 10 | 5 | 400 | **OPEN** — AG-04 / TICKET-16; only `interactive-review` works |
| FM-SR-05 | SQLite checkpoint store: WAL file not checkpointed on crash, journal replays stale data on next open | Resumed run replays already-executed observations; duplicate tool effects | 6 | 2 | 6 | 72 | SQLite WAL mode configured; crash recovery is SQLite's responsibility; tested |
| FM-SR-06 | Checkpoint schema version mismatch after upgrade (`_SCHEMA_VERSION` bump without migration) | `load()` returns old-format dict; new code expects missing keys; `KeyError` on resume | 6 | 2 | 4 | 48 | `_SCHEMA_VERSION = 1` hardcoded; no migration path yet |

**Top risk:** FM-SR-02 (RPN 576) — silently creates a bogus run; the wrong kind of "it works."

## P7: Audit Logging

**Description:** `AuditLogger.record()` → payload redaction → JSONL append with hash chain and
`fsync` → sink fan-out (OpenTelemetry, webhook, etc.) — across the full session lifetime.

| ID | Failure Mode | Effect | S | O | D | RPN | Mitigation Status |
|----|-------------|--------|---|---|---|-----|------------------|
| FM-AL-01 | Disk write `OSError` enters 30-second cooldown — all audit events during cooldown are in-memory only | Audit gap of up to 30 seconds of events on disk; governance / compliance hole | 8 | 3 | 6 | 144 | Cooldown is intentional to avoid I/O storms; `_disk_write_error` event appended in-memory; user not notified |
| FM-AL-02 | Two processes write to the same JSONL concurrently (NFS or shared `.teaagent/`) | Hash chain integrity broken; `verify_chain_integrity()` reports errors; events may be lost or interleaved | 8 | 2 | 5 | 80 | `file_lock` (fcntl) used on local FS; NFS advisory — ADR 0008 documents single-writer requirement |
| FM-AL-03 | Audit level `L3` (full trace) stores all payloads in plaintext including tool arguments and secrets | Secrets (API keys, tokens in commands) written to `.teaagent/runs/*.jsonl` at 0o600; readable by root or same-user processes | 9 | 3 | 5 | 135 | L3 docstring documents "no encryption at rest"; L2 (default) redacts; operator must set level intentionally |
| FM-AL-04 | Audit sink exception (OpenTelemetry, webhook) logged at `ERROR` but not surfaced to user or run result | Compliance sinks silently fail; telemetry gap goes undetected until audit | 6 | 4 | 8 | 192 | `logger.error` + `logger.warning` for failed sinks; `failed_sinks` count logged; no exception re-raised |
| FM-AL-05 | Redaction false negative — novel secret format not matched by `SENSITIVE_STRING_PATTERNS` | Secret leaks into JSONL at L2 (default) level | 8 | 3 | 8 | 192 | 7 regex patterns cover major formats (Bearer, sk-, JWT, AKIA, ghp_); custom patterns via `redaction_config`; pattern list must be maintained |
| FM-AL-06 | Audit file mode reset by process umask after `secure_audit_file()` → race with directory listing | Another user-space process reads the audit log before chmod completes | 5 | 1 | 7 | 35 | `chmod(0o600)` called after each write; race window is tiny; `os.fsync` precedes chmod |
| FM-AL-07 | `verify_chain_integrity()` not called automatically — chain breaks go undetected until manual audit | Tampered or corrupted audit log accepted as valid; governance assumption violated | 7 | 4 | 9 | 252 | `teaagent audit verify` CLI exists; not wired to CI or session-end check |
