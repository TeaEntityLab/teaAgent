# Daily-Driver UX Principles
# 2026-06-02

Principles for TeaAgent daily-use UX.

## Principles

1. Accuracy beats polish.
2. A command must execute, refuse, or ask for approval.
3. Lifecycle words are promises.
4. Cost is a trust signal.
5. Approval is the security model.
6. Root is part of user intent.
7. Undo must name its scope.
8. Evidence should be one command away.
9. Tests should match user paths.
10. Docs should guide the next action.

## Anti-principles

Avoid:

- Decorative counters.
- Aspirational help text.
- Silent fallback to stale state.
- Broad approvals for narrow tasks.
- Passing tests that bypass the UI path.
- Historical docs with no current-status front door.

## Design target

TeaAgent should feel like a careful operator cockpit: quiet, explicit, recoverable, and
honest about uncertainty.
