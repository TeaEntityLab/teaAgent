## TICKET-12 stop-gap — TUI `/cost` always showed $0.00

**Branch:** `fix/ticket-12-cost-accumulator`
**Priority:** P1 (user-visible lie)
**Bug reference:** CG-11 in `docs/analysis/daily-driver-third-pass-postfix-audit-2026-06-01.md`

### What was broken

`_session_cost_cents` is declared at `tui/__init__.py:186` and read by
`_handle_cost()` (line 744), `_handle_effort()` (762), and `_handle_budget()`
(791).  It was never incremented.  Every `/cost` or `/budget` output showed
`$0.00` regardless of how much the session had actually spent.

The REPL surface (`ChatSessionController`) already accumulated cost correctly
at `chat_session_controller.py:168`.  The TUI's `_run_agent_task` path called
`run_chat_agent` and had access to `result.cost_cents` but never added it.

### Fix (1 line)

```python
# tui/__init__.py — after result = run_chat_agent(...)
self._session_cost_cents += result.cost_cents
```

Inserted immediately after the `run_chat_agent` call ends (before
`store.logger_for_result`).  `_run_agent_task` is the single dispatch point
for all TUI agent execution (ask, run, resume), so accumulating here covers
every code path.

### Why not the full TICKET-12 migration?

The full fix is migrating the TUI to use `ChatSessionController` (which
already has correct accumulation).  That is a larger refactor.  This one-liner
provides the user-visible fix immediately while TICKET-12 is planned.

### Alternatives considered

- **Accumulate in `_handle_cost` from RunStore**: would require a DB query on
  every `/cost` invocation; fragile for in-memory databases and adds latency.
- **Adopt ChatSessionController now**: correct long-term approach but
  significantly larger diff; risks introducing regressions before QA.

### Collateral change

Two existing mocks in `tests/test_tui.py` (lines 1107, 1223) did not set
`cost_cents` on their `MagicMock` return values.  With the new `+=` line,
`float += MagicMock` would assign a `MagicMock` to `_session_cost_cents`,
corrupting type state.  Added `cost_cents=0.0` to both mocks.

### What this enables

- `/cost` shows real accumulated cost per session.
- `/budget remaining` and `/effort spent` fields are correct.
- Unblocks TICKET-12 full migration with a known-good baseline.

## TICKET-14 — Un-mask the test that hid CG-11

**Branch:** `fix/ticket-14-unmask-cost-test` (stacks on `fix/ticket-12-cost-accumulator`)
**Priority:** P1 (test integrity)
**Bug reference:** CG-16 in `docs/analysis/daily-driver-third-pass-postfix-audit-2026-06-01.md`

### What was broken

`test_tui_cost_shows_session_cost` (formerly line 1140) did:

```python
tui._session_cost_cents = 123.0   # inject directly
tui._handle_cost()
self.assertIn('$1.23', ...)
```

This tested `/cost` display formatting correctly but said nothing about whether
`_run_agent_task` ever updates `_session_cost_cents`.  All 104 TUI tests passed
green while the accumulation line was absent.

### Fix

Added `test_tui_run_agent_task_accumulates_cost` which drives the real dispatch
path:

1. Mocks `run_chat_agent` to return `cost_cents=150.0`.
2. Calls `tui._run_agent_task('test task')`.
3. Asserts `tui._session_cost_cents == 150.0`.
4. Runs a second task (`cost_cents=75.0`) and asserts additive accumulation
   (`150 + 75 = 225`).

The old test is kept (it still correctly validates `/cost` display formatting)
with a clarifying comment distinguishing it from the accumulation test.

### Why stack on TICKET-12?

The new test must pass on the fixed code.  Creating it on `main` (where the
accumulation line is absent) would produce a permanently-failing test that
nobody would know to associate with the accumulation fix.

### Alternatives considered

- **Delete the old test**: it still has value (formatting regression guard) so
  we keep it with a clarifying comment instead.
- **Rename the old test**: would communicate intent but at the cost of a
  misleading diff; comment is clearer.

## TASK-DD2-001 — Silent task drop in `teaagent chat "task"`

**Branch:** `fix/task-dd2-001-initial-task-passthrough` (stacks on `fix/ticket-14-unmask-cost-test`)
**Priority:** P0 (user trust — command silently does the wrong thing)

### What was broken

`teaagent chat "fix the auth bug"` parsed `fix the auth bug` into `args.task`
(via `add_agent_run_arguments(include_task_positional=True)` in
`_agent_parsers.py:634`) but then silently dropped it:

```
CLI parser → args.task = "fix the auth bug"
                ↓
chat_command()   ← never reads getattr(args, 'task', None)
                ↓
run_tui()        ← no initial_task parameter existed
                ↓
TeaAgentTUI.run()← no initial_task parameter existed
                ↓
User sees empty interactive REPL, task gone
```

The old `run_chat_repl()` in `cli/_handlers/_chat.py` DID support
`initial_task`, but `chat_command` delegates to `run_tui` (the TUI), not
`run_chat_repl`.

### Fix (three coordinated changes)

**`cli/_handlers/_chat.py` — `chat_command()`**: read the positional arg and
forward it:

```python
initial_task: str | None = getattr(args, 'task', None) or None
# ... (in the run_tui() call)
initial_task=initial_task,
```

**`tui/__init__.py` — `run_tui()`**: add parameter and forward to `tui.run`:

```python
initial_task: Optional[str] = None,   # new parameter
# ... (in tui.run() call)
initial_task=initial_task,
```

**`tui/__init__.py` — `TeaAgentTUI.run()`**: add parameter and execute the
task before the REPL loop:

```python
initial_task: Optional[str] = None,   # new parameter
# ...
if initial_task:
    try:
        self._run_agent_task(initial_task)
    except (OSError, ValueError, TypeError, RuntimeError) as exc:
        self.output_fn(f'error running initial task: {exc}')

while True:   # ← REPL loop starts here, after initial task completes
```

### Why execute in `run()` not `__init__()`?

Workspace defaults and TUI state are loaded at the start of `run()`.  Executing
the task in `__init__` would run before `provider`, `model`, and
`permission_mode` are resolved from TOML/state files.

### Why not modify `run_chat_repl`?

`run_chat_repl` is an older standalone function not on the main code path for
`teaagent chat`.  Fixing it there would fix the wrong entrypoint.

### Alternatives considered

- **Reject positional arg and print error**: user typed a task expecting it to
  run; silently ignoring and dropping into REPL is worse than running it.
- **Print a warning if task is ignored**: worse UX than just executing it.
- **Execute after first REPL prompt**: would confuse timing; task must run
  before the user is asked for input.

### Tests added

| Test | What it verifies |
|------|-----------------|
| `test_chat_command_forwards_initial_task_to_run_tui` | `chat_command` reads `args.task` and passes it as `initial_task` to `run_tui` |
| `test_run_tui_initial_task_executed_before_repl` | `_run_agent_task` is called with the initial task before the REPL loop starts |
| Updated `test_chat_command_forwards_params_to_run_tui` | Asserts `initial_task=None` when no positional task arg is present |

### What this enables

- `teaagent chat "fix the auth bug"` runs the task, then drops into the REPL
  for follow-up — the intended UX.
- Task is accumulated in `_session_cost_cents` via the TICKET-12 fix, so
  `/cost` after the initial task shows the real cost.
