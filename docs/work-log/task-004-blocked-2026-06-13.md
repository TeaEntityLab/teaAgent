## 1. Investigation findings (subagent, verified)

- The deprecation originates in `teaagent/policy.py` (~lines 113–117):
  `--approve-call-id` populates `preapproved_call_ids`, which warns
  "use full payload digest verification via scoped approvals instead."
- The modern mechanism, `ApprovalPresetStore.add_scoped_approval()`, binds an
  approval to a **payload digest and a `run_id`** — but `run_id` is generated
  at run start, so **no pre-run, non-interactive CLI flag can create a scoped
  approval today**. Headless flows (tests, demo, CI) therefore have exactly
  one explicit-approval path: the deprecated one.

## 2. Why the attempted migration was rejected

The first attempt switched the flagship tests and the five-minute-proof demo
to `--permission-mode workspace-write` with plan-declared file targets, and
removed the approval-record assertions. That makes the warning disappear by
**removing the approval gate from the proof**: Step 2 of the thesis ("every
mutation gated by an explicit approval record") would no longer be
demonstrated, and `run_evidence.approvals` assertions would be deleted —
which the assertion-regression pre-commit gate exists to block. A flagship
proof must demonstrate the approval pillar, not route around it.

## 3. Current state

- The three files are unchanged (reverted to `d736a1b` state) and green:
  `tests/acceptance/test_first_hour_e2e_flow.py`,
  `tests/acceptance/test_five_minute_proof_flow.py`,
  `scripts/five-minute-proof-demo.sh`.
- They intentionally keep using `--approve-call-id` and intentionally emit
  the DeprecationWarning until TASK-008 lands. This file is the recorded
  reason; do not "fix" the warning by weakening the proof.

## 4. Smallest unblock (TASK-008)

Add a pre-run scoped-approval CLI surface, e.g.:

```
teaagent run … --approve-tool workspace_write_file --approve-args-digest <sha256>
```

- Computes/accepts the payload digest up front; the runner binds it to the
  generated `run_id` at start, then flows through the **non-deprecated**
  scoped-approval verification.
- Acceptance: flagship tests + demo migrate to it with approval-record
  assertions **intact**; `-W error:preapproved_call_ids:DeprecationWarning`
  passes; `preapproved_call_ids` can then be scheduled for removal.
- Owner review recommended on the flag UX (it is daily-use surface).
